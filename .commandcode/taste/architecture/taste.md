- The strict access chain — page → component → hook (use-*.ts) → store → SDK → API, no page/component imports the SDK directly — is a non-negotiable convention the user expects enforced in phase plans and tracker docs. Confidence: 0.75
- Reusable forms belong in a dedicated forms folder, not built inline in pages using shadcn form primitives. Confidence: 0.65
- Before starting new development phases, close out all audit gaps and bug fixes first — ensure no invisible gaps remain ("lets close out all opened tasks and e2e todos.. before you proceed"). Confidence: 0.75
- When migrating to a replacement component/dependency library (e.g., Radix → a shared facet-components library), remove the superseded dependency and any vendored local component folder once the swap is complete — don't keep both in the package. Confidence: 0.75

- Determine user type through authentication, not URL conventions: unauthenticated/public users get the marketing/landing + public routes, authenticated devs/orgs get the protected dashboard — role-based routing decided by auth state, not by separate URL schemes (user: "the best way to detect the kind of user is through authentication"). Confidence: 0.75
- Authenticated users all get a dashboard split by user type: general users land on a web-wallet view (a web version of ArcWallet showing their held credentials), while dev/org users with ACTIVE tenant memberships land on the tenant-scoped console dashboard (tenants/orgs) — the discriminator is real membership/role data from the auth response, not guessed from the URL. Confidence: 0.7
- When shared/owned packages (e.g., @arcevo/facet-*) publish newer versions, proactively run a full-repo replacement audit across styling/tokens, icons, components, auth, and layout — swapping local duplicates for the packages' native exports rather than just bumping versions (user: "look through them to see what could be replaced repo wise... from the styling to the icons to the components and all... lets fully utilize them"). Confidence: 0.75
- In Next.js App Router pages, never call `useSearchParams()` in the page component itself — it bails out of static prerendering (missing-suspense-with-csr-bailout); move it into a Suspense-wrapped child component so the route stays statically prerenderable. Confidence: 0.7
