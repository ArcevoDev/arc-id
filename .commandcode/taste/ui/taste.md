# UI / Design
- Prefers landing/marketing pages to follow the shared design system's visual language — glassmorphism (tech-grid background with radial fade mask, soft blur glow, text-gradient headlines, glass cards/CTAs) as seen in the facet landing — rather than plain static hero sections. Confidence: 0.8
- Likes modern animated text in heroes — typewriter/typing animations cycling multiple phrases with a blinking caret, or text-box-style effects — over static headlines ("we could even have some typing animation or any other modern text animation... could even make it text-box like"). Confidence: 0.85
- Wants UI work done "thinking in design systems": reuse the established design-system patterns and ready-made components rather than ad-hoc, one-off styling solutions. Confidence: 0.8
- When the shared component library ships updated/added ready-made components (Navbar, Footer, FeedbackPage, DataTable, EmptyState, ConfirmAlertDialog, Toaster, …), audit the library's new export surface before writing UI and replace hand-rolled equivalents in the consuming app — keep pages in sync with the library's latest capabilities instead of maintaining bespoke versions. Confidence: 0.8
- Prefers the pill-style Navbar variant (the pattern the facet landing reference uses) as the established nav for the public site; when the library offers variants, match the design system's reference rather than inventing a new one. Confidence: 0.65
- Prefers poetic, evocative, human copy over generic UI wording — user self-identifies as a "poetic dev" and explicitly asks for more poetic terms in public-facing copy (e.g., "Begin your journey" over "Get started", "One key, every sector" over "Sector-agnostic by design", "Speak your mind" over "Feedback"). Confidence: 0.9
- Wants consistent spacing and layout rhythm across pages/sections (uniform section spacing, max-width containers, consistent vertical rhythm) rather than ad-hoc per-page spacing. Confidence: 0.7
- Button icon+label pairs must keep the icon beside the label on all screen sizes — prevent wrapping below the text on small screens (inline-flex + gap + whitespace-nowrap + shrink-0 icon). Confidence: 0.75
- Avoids em-dashes and en-dashes in UI copy, table fallback values, metadata templates, and comments — use plain hyphens instead (a stated constraint the user expects enforced across pages and docs). Confidence: 0.65
- Pages and the landing must respect the light/dark theme — use semantic theme tokens (text-foreground, text-primary, text-muted-foreground, glass/text-gradient utilities) rather than hardcoded colors, so no page forces a single appearance. Confidence: 0.6
- Wants a visible theme toggle in the site nav — use the component library's built-in theme-toggle variant (e.g., Navbar `showThemeToggle`) rather than removing or hand-rolling the control; the user explicitly checks that the toggle exists. Confidence: 0.65
- Mobile hamburger/nav dropdowns must render their full content on mobile — no clipping or floating off-position; provide an explicit mobile menu layout so everything (links, divider, CTAs) displays completely. Confidence: 0.7
- Prefers concise marketing/typewriter copy — shorter phrases that still "make the hit" over longer prose ("make the typing txt phrases, shorter and still make the hit"); the hero typewriter should cycle about 5-7 short phrases, not longer prose. Confidence: 0.7
- Hero/typewriter copy must stay truthful and canonical to what the system actually does (SD-JWT credentials, passkeys, OAuth2/OIDC, non-custodial identity) — even when poetic, do not invent or exaggerate claims ("do not forge words, be truthful and canonical"). Confidence: 0.6
- Prefers hero typewriter phrases to read as a grammatical continuation of the static headline phrase (e.g., "One identity," followed by lowercase cycling completions like "verified once, trusted everywhere." / "one key, every door.") — the cycling text should flow from the preceding comma as one continuous sentence rather than standalone capitalized phrases. Confidence: 0.7
- Auth surfaces should use the shared auth package's ready-made forms (facet-auth `SignIn`/`SignUp`/`MfaDialog`/`ForgotPasswordForm`/`ResetPasswordForm`) instead of hand-rolled login/register/mfa forms — the user explicitly asks "why are we not using the forms components or the auth forms from our facet pkgs." Confidence: 0.85
