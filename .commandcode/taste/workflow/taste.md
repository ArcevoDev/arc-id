# Workflow
- When confirming a published package is ready to build on, verify the actual published npm artifact (downloaded tarball/bundle) against the consuming app's real API surface (routes, types, envelope/bare response handling) — not just the repo source or registry metadata. Confidence: 0.85
- Prefer consuming shared packages as external npm dependencies updated via version bumps; upstream in-progress structural changes should not block downstream development. Confidence: 0.8
- Before applying bulk doc updates, show diffs to the user for review first. Confidence: 0.60
- Before a frontend/architecture rebuild, first thoroughly audit both the upstream dependency codebase and the target codebase to build a complete overlap map of what to purge, keep, and refine. Confidence: 0.75
- When auditing a sibling or dependency codebase, produce a categorized analysis covering: what exists (inventory), consumption overlap map, blockers, design inconsistencies, and ranked optimization opportunities for scalability & third-party dynamism — each with actionable recommendations. Confidence: 0.70
- When auditing a codebase that has documented claims (README, AGENTS.md, CLAUDE.md, etc.), explicitly verify each claim against actual codebase reality and produce a "claims vs reality" comparison table — tracking what's been fixed, what's still broken, and what's changed since the doc was written. Confidence: 0.75
- When automated exploration/subagent tools fail, fall back to manual systematic exploration (reading files one by one in a structured order) rather than retrying the failed automation. Confidence: 0.75
- After an interrupted session (e.g., IDE crash), trace the repository state — git status/diff/log, session artifacts like `.agent/output.txt`, untracked directories, and lockfile/package.json — to reconstruct what was completed versus what is still open; report this as a structured "what exists / what's still open" summary and ask how the user wants to proceed rather than acting unilaterally. Confidence: 0.75
- When shell commands fail to resolve paths that clearly exist (e.g., Windows CRLF/encoding path issues), fall back to the dedicated directory/file reading tools instead of retrying the failing shell command. Confidence: 0.60
