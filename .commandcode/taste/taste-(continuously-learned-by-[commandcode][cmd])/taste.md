# Taste (Continuously Learned by [CommandCode][cmd])
- Use pnpm as package manager. Confidence: 0.95
- Leans toward global CLI installs for cross-repo convenience (running commands from any terminal) and considers removing redundant local devDependency copies in favor of a single global installation, though defers to version-pinning and CI parity when tools are workspace-managed as devDependencies. Confidence: 0.5
- Pin exact versions of published third-party/published packages that lack test infrastructure (or are pre-stable), rather than `^` ranges — to protect against a breaking bump mid-work. Confidence: 0.65
- ESM only — never emit `require()` / `module.exports`. Confidence: 0.95
- Vitest for tests, never Jest. Confidence: 0.95
- Zod for all runtime validation (`.schemas.ts` files). Confidence: 0.9
- Uses Zustand for client-side state management in shared store packages — `@arcevo/facet-store` exports React hooks (`useAuthStore`, `useTenantStore`) backed by Zustand, with `react`/`react-dom` declared as peerDependencies (hooks consume React at the boundary). Confidence: 0.85
- After any code change, run `pnpm typecheck` (tsc) AND `pnpm test` (vitest) — don't rely on vitest alone, as it can miss type errors that tsc catches. "Green" means both pass. Confidence: 0.85
- For multi-site migrations (e.g., replacing authorization patterns across the codebase): replace call sites one module at a time, testing after each module, rather than making all changes then testing in one pass. Confidence: 0.75
- Never create manual hand-written Prisma migrations — use `prisma migrate diff` or `prisma migrate dev` to generate SQL from schema changes. Confidence: 0.70
- For route-level tests whose import chain reaches the real Prisma bootstrap (`buildClient` → `withTenantIsolation` → `client.$extends`), mock `@/core/db/prisma` (plus the audit service) like the established passing route tests do — mock the module where the side effect lives, not just the leaf package. Confidence: 0.8
- When the route under test uses the array form of `$transaction([...ops])`, the test's mock DB must resolve array elements (e.g., `Promise.all`) — the callback-form mock alone leaves the tx unresolved and 500s. Confidence: 0.8
- Match the established test's Fastify auth decorator (all of `requireUser`, `requireScope`, `requirePlan`, `requireAal2`, `requireElevated`, `requirePermission`) when decorating `auth` in a route test, so typecheck passes. Confidence: 0.75
- Avoid broad process-killing commands like taskkill. Confidence: 0.65
- Before "fixing" an import that a bundler/runtime flags as undefined, verify the package's real export surface (build/exports.js, exports.d.ts, runtime evaluation) — the code may be valid and the crash may come from dependency version skew or a stale bundle/cache; don't churn code that isn't the root cause. Confidence: 0.7
- When rendered/runtime output is incomplete or wrong, isolate whether the defect is in the dependency or the consumer before changing consumer code — write minimal standalone repro scripts that exercise the raw package directly (raw template-tree path vs React-element path, inspect the intermediate tree) to pinpoint where output is dropped; this is how the missing email-body bug was proven to be in `@arcevo/facet-emails` (its `toReactNode` drops React-element children), not in the repo's templates. Confidence: 0.7
- Respect the user's own running dev processes: don't kill their active terminal sessions (e.g., their running Metro) to clear caches — use non-destructive fixes (clean cache on next start, targeted file edits) and let the user restart with a `--clear` flag when needed. Confidence: 0.7
- Prefer the public API surface of directly-declared dependencies over subpath/transitive imports: before importing from a package subpath, verify the underlying package is a declared direct dependency — don't rely on undeclared transitive deps (e.g., use facet-components' root exports like `Icon`/`lucideIconMap`/`cn` rather than `@arcevo/facet-components/icons` when lucide-react is only a transitive dep). Confidence: 0.65
- When swapping to a replacement component library, keep the existing consumer-facing API stable by writing a thin adapter module over the new package's API (e.g., rebuild `icon-registry.ts` from `lucideIconMap` so `Icons.foo`/`IconName` keep working across all consumers) instead of rewriting every call site. Confidence: 0.35
- Prefer lucide icons — the team is "lucide lovers" (stated outright); when the facet packages ship the full lucide registry, use the native `<Icon name="…" />` rather than a different icon set or a hand-rolled registry. Confidence: 0.95
- Facet SDK `ApiResponse<void>` mutations (revoke/delete/deregister/disable/delete-account) carry no `.data` — check `!result.error` for success, never `result.data`; the latter shows a false error on success and leaves local state stale. Confidence: 0.8
- On this machine, background shell runs with `> file 2>&1` redirection can silently produce empty capture files (observed for vitest, tsc, and `next build`) — rely on the background run's exit code, or re-run in the foreground with a long timeout to surface the real output/error; PowerShell capture via `$out = & ... 2>&1 | Out-String; $out | Out-File -FilePath <path outside repo> -Encoding utf8` is the reliable way to capture text. Confidence: 0.7
- To actually surface the real typecheck/test error text (not just the exit code), the reliable read-back is: run the command in the **foreground**, redirect to a file under `scratch-e2e/<name>.txt` (foreground guarantees the file is fully written before reading), then read it back with a `node -e` one-liner — `fs.readFileSync(...) + console.log(...)`, usually sliced (`.slice(0, 4096)` for the head, `.slice(-N)` for the tail) or wrapped in a length check that prints a custom pass/fail message. A plain file read can't slice or emit a custom verdict, so the one-liner is the go-to when the background capture came back empty. Confidence: 0.65
- On this 8GB-RAM machine, a stalled `next build`/typecheck is usually memory pressure from the user's live dev servers and background pnpm installs rather than orphaned processes — before killing anything, check free memory (`wmic OS get FreePhysicalMemory`) and identify the heavy node processes; when asked how to proceed, the user prefers to free memory themselves (close apps) and let their own installs finish rather than have the agent kill processes (re-affirmed this session: user closed apps and chose to wait out the pnpm install, and asked the agent "what do i need to do about that" for actionable guidance). Confidence: 0.7
- No unused imports or declarations: with the `react-jsx` JSX transform, drop `import * as React` unless `React.*` types/values are actually referenced, and don't declare props/imports that go unused — the user stated it outright ("let us ensure there are no stale imports, like the react imports... and we do not declare what's not used... if it really matters, then we should fully utilize it"), meaning imported things should either be removed or genuinely used. Confidence: 0.7
