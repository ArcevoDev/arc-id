### 1.3 Every SDK path maps to a real arc-id route

Extracted 50+ hardcoded request paths from the published bundle and matched

### 1.4 Envelope handling matches arc-id exactly

- Domain routes respond `{ success: true, data }` → client unwraps by default
  (verified in login.route.ts, issue.route.ts, did.route.ts, offer.route.ts)
- Protocol/public endpoints respond bare → `bare: true` option used
  (verified in tokens.route.ts, jwks.route.ts, userinfo.route.ts,
  verify-session.route.ts, status.route.ts)
- `ApiResponse<T> = { data, error } | { data: null, error }` — identical to
  arc-id's inline SDK contract
- Plan-gate fields (`currentPlan`, `requiredPlan`) surfaced on 402 errors

### 1.5 401 auto-refresh — the old blocker is closed

`ArcIdClient` supports `onTokenRefresh` (retry exactly once) and
`onAuthCleared`. Wired into the request retry loop (client.ts:170-178) with
real unit tests. Matches arc-id's inline client behavior.

### 1.6 Facet SDK has its own tests

- `client.test.ts` — envelope unwrap, bare responses, error mapping,
  401 refresh/retry/clear, all HTTP verbs
- `auth.sdk.test.ts` — login (MFA + no-MFA), register, verifyMfa,
  forgotPassword, refresh normalization, revokeSession, error surfacing

## 3. Execution plan — integrate facet into arc-id

### Phase 0 — Guardrails
- Pin exact versions in package.json: `@arcevo/facet-sdk@1.0.1`,
  `@arcevo/facet-components@1.1.0`, `@arcevo/facet-auth@1.0.3`,
  `@arcevo/facet-layout@1.1.0`, `@arcevo/facet-tokens@1.0.1` (no `^`)
- Add to dependencies + `pnpm install`

### Phase 1 — SDK swap (lowest risk, do first)
- Replace `src/sdk/*` with `@arcevo/facet-sdk`
- Keep arc-id's `src/sdk/index.ts` as a thin adapter that re-exports
  `ArcIdClient` + domain SDKs, or import facet-sdk directly from hooks
- Rewire token lifecycle: `setAccessToken` + `onTokenRefresh` →
  Zustand auth store getters (same pattern as the current inline client)
- Delete inline `src/sdk/*` domain modules after adapter verifies

### Phase 2 — Tokens
- Import `@arcevo/facet-tokens/tokens.css` in globals.css
- Remove duplicated `:root` CSS variable declarations (keep `@theme`,
  `@utility`, `@keyframes` blocks)

### Phase 3 — Components
- Replace `src/components/ui/*` with `@arcevo/facet-components`
- Update imports to `@arcevo/facet-components`
- Purge inline shadcn components after verification

### Phase 4 — Auth
- Replace `src/components/auth/*` with `@arcevo/facet-auth`
- Bridge decision: either replace Zustand auth store with ArcProvider
  (React Context), or wrap ArcProvider and sync to Zustand for backward
  compat
- Preserve tenant hydration logic in `AuthProvider` (arc-id keeps this)
- MFA flow: confirm facet-auth MfaDialog is wired to `verifyMfa` (the old
  blocker — placeholder stub — must be resolved)

### Phase 5 — Layout
- Adopt `@arcevo/facet-layout` shells (ConsoleLayout/AuthLayout) or keep
  arc-id layout wrapper initially and migrate incrementally

### Phase 6 — Validation
- `pnpm test` (395 tests) — must stay green
- `pnpm typecheck`
- `pnpm build:web` + `pnpm build:api`
- Manual smoke: login → MFA → tenant switch → passkey

### Keep in arc-id (facet has no equivalent)
- `src/store/*` — Zustand stores (auth, tenant, ui)
- `src/hooks/*` — page-level hooks
- `src/providers/auth-provider.tsx` — tenant hydration
- `src/styles/globals.css` — `@theme`, `@utility`, `@keyframes` only
- All pages — import from hooks, never SDK directly
