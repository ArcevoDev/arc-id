## CRITICAL BUGS FIXED THIS SESSION

### 1. `src/sdk/identity.sdk.ts` — Corrupted (null bytes)
- **File was completely zeroed out** — `\x00` bytes from line 1.
- Caused all 4 identity SDK tests to crash with `Invalid Character`
- Rewritten from scratch with `list()`, `suspend()`, `reinstate()` methods matching the test expectations and backend routes.

### 2. `src/sdk/auth.sdk.ts:logout()` — Missing required body
- `logout()` called `client.post("/auth/logout")` with no body.
- Backend route requires `{ sessionId }` (z.string().min(40).max(128)) via Zod.
- **Every call to `auth.logout()` returned 400** — logout was completely broken.
- Fixed: `logout(sessionId: string)` now sends `{ sessionId }`.

### 3. `src/sdk/tenant.sdk.ts:list()` — Calls non-existent route
- `tenants.list()` called `GET /tenants` which has no backend route.
- Always returned 404. Removed entirely — must implement backend route first.

### 4. `src/modules/auth/repositories/identity.repository.ts:findForAuth()` — Missing passkeys
- `login.flow.ts` line 93 reads `(identity as any).passkeys?.length > 0` to determine `hasPasskey`.
- But `IdentityRepository.findForAuth()` query did NOT include `passkeys` in its `include`.
- **Result: `hasPasskey` was always `false`**, so users with registered passkeys were incorrectly prompted to enroll MFA when `TenantPolicy.requireMfa = true`.
- The test at `login.flow.test.ts:223` mocks the raw identity directly (bypassing the repository) so it never caught this.
- Fixed: added `passkeys: true` to the `include` clause.

### 5. `src/modules/billing/validators/billing.schemas.ts` — Corrupted (null bytes)
- Same corruption pattern as `identity.sdk.ts`. Restored from git.

### 6. `src/modules/auth/flows/email-verify.flow.test.ts` — Suite crash
- Imported `auditService` from `@/modules/audit/services/audit.service` which imports `@/core/db` → `prisma.ts` → tries to build a real PrismaClient with `$extends`.
- `vi.mock("@prisma-client")` provides `PrismaClient: vi.fn()` but the mock doesn't have `$extends`.
- Flow was already using `auditService.log()` in production code since the commit that added the audit call, but the test never mocked `auditService`, so the import chain reached real Prisma code.
- Fixed: added `vi.mock("@/modules/audit/services/audit.service")` in test setup.

## CI/CD APPROACH RECOMMENDATION

Since Docker isn't installed locally and the PC is lagging:

**Recommended: GitHub Actions only (no Terraform, no K8s locally).**

Rationale:
- Terraform/K8s require tooling installation and cluster access — both add overhead without Docker
- GitHub Actions can run everything in the cloud: `pnpm test`, `pnpm typecheck`, Prisma migrations
- For deployment: GitHub Actions can SSH-deploy to a VPS or use a cloud platform's CLI
- You add Terraform/K8s later when you have a team or a multi-node deployment

**What's already in `.github/workflows/`:**
- `ci.yml` — test + typecheck on PR
- `deploy-api.yml` — deploy API to production
- `deploy-web.yml` — deploy frontend
