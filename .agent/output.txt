## ARC-UI AUDIT (2026-07-29) — Cross-reference

### What arc-ui is

A monorepo (pnpm workspace) at ../arc-ui producing 5 publishable packages:

| Package | Contents | Status |
|---------|----------|--------|
| @arc-ui/tokens | Alpha Palette (OKLCH), typography, spacing, sub-brands, CSS variables | ✅ Done |
| @arc-ui/sdk | Pure fetch SDK — ArcIdClient + 10 domain classes (auth, passkey, identity, oauth, tenant, billing, webhooks, audit, idp, vc) | ✅ Done |
| @arc-ui/components | 25 Radix-based UI components (Button, Input, Card, Dialog, Select, etc.) + glass/glow variants | ✅ Done |
| @arc-ui/auth | React context auth system — ArcProvider, SignIn state machine, SignUp, Guard, MfaDialog, UserButton, 7 forms, 5 domain presets | ✅ Done |
| @arc-ui/layout | Domain-configurable app shells — ConsoleLayout, AppLayout, LandingLayout, Sidebar, Topbar, PageHeader, TenantSwitcher, 5 presets | ✅ Done |

### Overlap with arc-id (near-exact duplication)

arc-id's own frontend has inline copies of everything arc-ui provides:
- src/components/ui/* (25 shadcn components) ↔ @arc-ui/components
- src/components/auth/* (5 simple forms) ↔ @arc-ui/auth (more complete — state machine, presets, 7 forms)
- src/sdk/* (11 modules) ↔ @arc-ui/sdk (identical API response shape)
- src/styles/globals.css :root variables ↔ @arc-ui/tokens/tokens.css (same values, same names)

### What arc-id keeps

Zustand stores (auth, tenant, ui), hooks (use-*, 11 files), providers (AuthProvider with tenant hydration), pages (import from hooks), layout wrapper (until adopting @arc-ui/layout).

### Gaps to close before arc-id adoption

Blockers:
- SignIn MFA challenge is a placeholder stub (not MfaVerifyForm)
- handlePasskeyAuth and handleForgotPasswordSubmit don't call SDK methods
- No test infrastructure — zero tests across arc-ui monorepo

Design inconsistencies:
- layout/UserMenu duplicates auth/UserButton with different approach (custom HTML vs DropdownMenu)
- No PostCSS config in packages (resolved in apps/docs only)

### Optimization for scalability & third-party dynamism

1. **Type strictness** — `Record<string, unknown>` overuse in SDK types. Cast patterns like `as unknown as AuthUser` are brittle. Strict interfaces with branded types would make third-party integration safer.
2. **Icon library** — 25+ inline SVG paths (~20 lines per component). Lucide or Radi Icons would reduce bloat and enable runtime icon swapping per domain.
3. **Router adapter** — Sidebar uses `window.location.pathname`. A router adapter interface (Next.js Link, Remix NavLink, React Router NavLink) would make it framework-agnostic.
4. **Schema-driven validation** — Auth forms do manual client-side validation. react-hook-form + zod integration would make forms robust for third-party consumers.
5. **Domain preset registry** — Currently 5 hardcoded presets. A `registerDomainPreset()` API would let third parties add custom presets without forking.
6. **Theme persistence** — `data-theme` toggle works but doesn't persist to localStorage or respect `prefers-color-scheme`. Adding both would match production expectations.
7. **Bundle analysis** — tsup CLI flags with no code-splitting config. Adding `--metafile` + bundle visualizer would catch bloat before publishing.
8. **CSS build pipeline** — tokens.css copied via `fs.cpSync`. Needs PostCSS + autoprefixer + minification for a self-contained published package.
9. **Build orchestration** — No turbo/nx. Root `pnpm build` runs sequentially. Incremental builds would be faster with task orchestration.
10. **A11y audit** — Radix primitives provide baseline accessibility, but compounded components (SignIn state machine, MfaDialog phases) need keyboard navigation + screen reader testing before third-party use.

### Integration tests: deferred

Real-Postgres integration tests now documented as **P3 — deferred until arc-ui ships**. Rationale:
- SDK tests (73) run via `fastify.inject()` with mock DB covering full API surface
- 395 mock-DB flow tests provide good regression coverage
- Real Postgres tests would add complexity (testcontainers, CI service containers) without immediate ROI
- Timing: after arc-id consumes arc-ui and the frontend contract stabilises, integration tests become the next reliability layer
